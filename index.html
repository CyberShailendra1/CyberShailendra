How to Find OWASP Vulnerabilities

The OWASP Web Application Top 10 is the definitive standard for web security. Below is a practical, step-by-step guide on how each vulnerability is discovered during a real penetration test or bug bounty hunt.

A01
🔓
Broken Access Control
Critical

Occurs when users can act outside of their intended permissions — accessing other users' data or admin functions.

  • 01 Map all endpoints using Burp Suite Spider or manual crawling
  • 02 Test IDOR by changing IDs in URLs, body params, headers (e.g. /user/123 → /user/124)
  • 03 Try accessing admin routes without privilege (e.g. /admin/dashboard)
  • 04 Check forced browsing by guessing file paths or API endpoints
  • 05 Test horizontal vs vertical privilege escalation
Burp Suite Postman ffuf Autorize
A02
🔑
Cryptographic Failures
Critical

Weak or missing encryption exposing sensitive data in transit or at rest — passwords, tokens, PII.

  • 01 Intercept traffic with Burp Suite — check for HTTP (not HTTPS) usage
  • 02 Inspect cookies: look for sensitive data, missing Secure/HttpOnly flags
  • 03 Check JS files for hardcoded secrets, API keys, passwords
  • 04 Use testssl.sh to identify weak cipher suites or expired certs
  • 05 Look for Base64-encoded sensitive data instead of encryption
Burp Suite testssl.sh truffleHog gitleaks
A03
💉
Injection (SQLi / XSS)
Critical

Untrusted data sent to interpreters — SQL, OS, LDAP. Leads to data exfiltration, auth bypass, RCE.

  • 01 Identify all input fields: search bars, login forms, URL params, headers
  • 02 For SQLi: inject ', ' OR 1=1--, boolean/time-based payloads
  • 03 Use sqlmap to automate SQLi discovery and exploitation
  • 04 For XSS: inject <script>alert(1)</script> in all reflection points
  • 05 Test stored XSS in profile fields, comments, file uploads
sqlmap Burp Suite XSStrike Dalfox
A04
🏗️
Insecure Design
High

Flaws in architecture and design — missing threat modelling, insecure business logic at the design level.

  • 01 Map the application's business logic and user flows manually
  • 02 Test rate limiting: can you spam password resets or OTPs?
  • 03 Test payment logic: price manipulation, coupon stacking, negative values
  • 04 Look for multi-step process flaws — can you skip steps?
  • 05 Check account recovery flows for predictable tokens or insecure questions
Burp Suite Manual Testing OWASP WSTG
A05
⚙️
Security Misconfiguration
High

Default credentials, open cloud storage, verbose error messages, unnecessary features enabled.

  • 01 Run Nikto to detect server misconfigurations and exposed files
  • 02 Check HTTP response headers (missing X-Frame-Options, CSP, HSTS)
  • 03 Look for exposed admin panels: /phpmyadmin, /admin, /.git, /backup
  • 04 Test default credentials on login pages
  • 05 Search for sensitive files: .env, web.config, robots.txt, sitemap.xml
Nikto dirsearch gobuster nuclei
A07
🚪
Identification & Auth Failures
Critical

Broken authentication, weak session tokens, missing MFA — leading to account takeovers.

  • 01 Test for username enumeration via login error differences
  • 02 Brute-force login forms with Hydra or Burp Intruder (rate-limit bypass)
  • 03 Inspect session tokens — check entropy, predictability, JWT weaknesses
  • 04 Test JWT with alg:none, RS256→HS256 confusion, weak secrets
  • 05 Check for session fixation and session not invalidated on logout
Hydra jwt_tool Burp Suite hashcat
A08
📦
Software & Data Integrity Failures
High

Insecure deserialization, unverified software updates, CI/CD pipeline vulnerabilities.

  • 01 Identify serialized objects in cookies, params (Java, PHP, Python pickles)
  • 02 Test deserialization with ysoserial or phpggc payloads
  • 03 Check update mechanisms — are they integrity-verified?
  • 04 Inspect JS imports for unverified CDN dependencies
ysoserial phpggc Burp Suite
A10
🌊
Server-Side Request Forgery
Critical

SSRF forces the server to make requests to internal/external systems — leading to cloud metadata theft or RCE.

  • 01 Find parameters that accept URLs or IPs (fetch URL, webhook, PDF generator)
  • 02 Try internal addresses: http://127.0.0.1, http://169.254.169.254 (AWS metadata)
  • 03 Use Burp Collaborator to detect blind SSRF via DNS/HTTP callbacks
  • 04 Try protocol smuggling: file://, gopher://, dict://
Burp Collaborator SSRFmap interactsh

The OWASP Mobile Application Security (MAS) framework defines the Mobile Top 10 — the most critical vulnerabilities in Android/iOS apps. Here's how to find each one using real-world tools and techniques.

M1
🔐
Improper Credential Usage
Critical

Hardcoded credentials, API keys, or tokens embedded in the APK's source code or config files.

  • 01 Extract APK: pull from device using adb pull or download from APKPure
  • 02 Decompile with jadx-gui or apktool to get readable Java/smali code
  • 03 Search for keywords: "password", "secret", "api_key", "token" in source
  • 04 Inspect res/values/strings.xml and assets/ for hardcoded values
  • 05 Use truffleHog or grep on decoded APK folder
jadx-gui apktool adb grep
M2
🛡️
Inadequate Supply Chain Security
High

Vulnerable third-party libraries, outdated SDKs, or compromised dependencies in the APK.

  • 01 Decompile APK and inspect build.gradle for third-party dependencies
  • 02 Cross-reference libraries with known CVEs using MobSF or OWASP Dependency Check
  • 03 Check if APK signing certificate is valid and untampered
  • 04 Look for debug builds using apktool: check AndroidManifest.xml for android:debuggable="true"
MobSF apktool OWASP DepCheck
M3
🔒
Insecure Authentication & Auth
Critical

Weak auth mechanisms, missing token validation, insecure biometric implementation.

  • 01 Intercept API calls with Burp Suite via proxy setup on emulator/device
  • 02 Test if JWT/session tokens are validated server-side or just client-side
  • 03 Try bypassing login by modifying responses: change "false" → "true" in auth response
  • 04 Test OTP brute-force and rate limiting on login endpoints
  • 05 Check if biometric auth can be bypassed via Frida hooks
Burp Suite Frida Objection jwt_tool
M4
📂
Insufficient Input/Output Validation
High

Missing validation on inputs leading to SQLi, XSS in WebViews, command injection, or path traversal.

  • 01 Test all app input fields with SQLi and XSS payloads via Burp Suite
  • 02 If app uses WebView, test for JavaScript injection and XSS
  • 03 Check deep links and intent data for unvalidated user-controlled input
  • 04 Test file upload functions: path traversal in filename, MIME type bypass
Burp Suite Drozer adb Manual
M5
💾
Insecure Communication
Critical

Plain HTTP usage, missing certificate pinning, accepting invalid/self-signed certs — enabling MitM attacks.

  • 01 Set up Burp Suite as proxy and install CA cert on Android device/emulator
  • 02 Intercept all API traffic — check for plain HTTP endpoints
  • 03 If cert pinning is present, bypass using Frida or Objection: objection --gadget "appname" explore → android sslpinning disable
  • 04 Test for weak TLS versions using testssl.sh on the server
Burp Suite Frida Objection Wireshark
M6
🗄️
Inadequate Privacy Controls
High

Sensitive data stored unencrypted on device — shared preferences, SQLite DBs, log files, external storage.

  • 01 Use adb shell to access app's data directory: adb shell → run-as com.app.package → ls
  • 02 Check shared_prefs/*.xml for tokens, passwords, PII in plaintext
  • 03 Pull SQLite databases: adb pull /data/data/com.app/databases/app.db
  • 04 Check external storage: /sdcard/ for sensitive files
  • 05 Read logcat output: adb logcat — look for credentials, tokens in logs
adb SQLite Browser MobSF logcat
M7
🧩
Insufficient Binary Protections
Medium

No obfuscation, no root detection, no anti-tampering — making reverse engineering trivial.

  • 01 Decompile APK with jadx-gui — if code is readable with no obfuscation, flag it
  • 02 Check if root detection exists and bypass it using Magisk + MagiskHide or Frida
  • 03 Use objection to check for emulator/debugger detection and bypass it
  • 04 Check if ProGuard/R8 obfuscation is enabled in build config
jadx-gui Frida Objection Magisk
M8
🔧
Security Misconfiguration
High

Debug mode enabled, backup enabled, exported components, weak permissions — common misconfigurations in AndroidManifest.xml.

  • 01 Decode AndroidManifest.xml using apktool: check android:exported, android:debuggable, android:allowBackup
  • 02 Use Drozer to enumerate exported activities, services, content providers
  • 03 Test exported activities directly: adb shell am start -n com.pkg/.ActivityName
  • 04 Check Firebase/cloud config files (google-services.json) for public read access
apktool Drozer adb MobSF
